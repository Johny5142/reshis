# Итоговый аудит «Решись Авиа» · 14 ноября 2026 года

## 1. Вердикт

Рабочая копия готова к локальной демонстрации. Обязательный вариант C раздела «Разработка» выполнен. Есть расхождение с буквальным требованием к дополнительному графику и риск передать неполные исходники. Критических ошибок в проверенных сценариях не обнаружено. Готовность публичного сайта пока не подтверждена.

## 2. Объём проверки

Основание — страницы 12–14 [конкурсного ТЗ](napravlenie-tekhnologii-zadacha-prodvinutogo-urovnia-59.pdf). Проверены путь от формы до сохранённого прогноза, рабочие CSV, схема и обработчики API, SQLite, сессии, лимиты, компоненты графика и истории, тесты, параметры Vite, Docker и Nginx. Предыдущие отчёты использованы для выбора адресных проверок. Для 155 рейсов и одного процесса API загрузка каталога в память и локальная SQLite соответствуют масштабу задачи.

## 4. Независимый расчёт

Десятичная арифметика по двум рабочим CSV, без импорта формулы приложения. Квантили ниже перечислены в порядке от 0,1 до 0,9.

- **MOW-AER, 01.06, 9 000 ₽.** Базовая цена 9 000, чувствительность 0,141, поправка нулевая. Спрос и продажи: 732 / 759 / 778 / 794 / **809** / 824 / 841 / 860 / 886. Все значения ниже 900 мест.
- **MOW-KGD, 19.06, 14 000 ₽.** Базовая цена 7 500, поправка 0,0957 × 6 500 = 622,05. Исходный спрос: −409,05 / −332,05 / −277,05 / −229,05 / **−185,05** / −141,05 / −93,05 / −38,05 / 38,95. При 450 местах первые восемь сценариев дают нулевые продажи, девятый — 38,95. Исходная медиана получена из 437 базовых пассажиров. Преобразованный интервал равен [0; 38,95].

Сервер сохраняет дробную точность и возвращает обе трактовки спроса. Тесты также покрывают точный ноль, нулевую вместимость, насыщение продаж и восстановление прежнего JSON истории без перезаписи базы.

## 5. Интерфейс

Chrome подтвердил регистрацию и повторный вход, выход и истечение сессии, смену темы, расчёт, отмену устаревшего ответа при смене параметров и восстановление истории. Проверены девять точек, выбор квантиля, медиана, линия мест, подписи, раскрываемые таблицы и интервал при частичном и полном обнулении. Пройдены проверки узких экранов. Интерфейс прямо указывает, что 80% — номинальный уровень. В коде предусмотрены состояния загрузки, пустой истории, ошибок API и сетевого сбоя. Отдельный браузерный эксперимент с отключением API и инструментальное измерение контрастности всех элементов не проводились.

## 6. Безопасность

Проверены транзакция регистрации с откатом, уникальность нормализованного email, Argon2id, отзыв и истечение сессий, HttpOnly/SameSite/Secure, контроль Origin и лимиты IP/email. Штатные тесты охватывают конкурирующую регистрацию и ошибки SQLite. База открывается на этапе запуска приложения. Запрос истории фильтруется по владельцу. Среди отслеживаемых файлов нет .env, SQLite, PEM или KEY; выборочный поиск распространённых сигнатур ключей совпадений не дал. История Git на секреты не сканировалась.

## 7. Docker и конфигурация

Тесты проверили вывод Compose CLI, применение шести параметров лимитов и учёт доверенного прокси средствами Uvicorn. Compose требует HTTPS-origin и явный адрес peer, фиксирует Secure-cookie, публикует API на loopback и монтирует том SQLite. Nginx задаёт X-Forwarded-For из адреса соединения и завершает TLS. Docker Engine недоступен. Сборка образа, сертификат, реальные клиентские IP и сохранность базы после пересоздания контейнера на VDS не проверены.

## 9. Перед сдачей

Собрать полный снимок исходников без SQLite с аккаунтами, секретов и зависимостей. Проверить запуск из него. Для полного соответствия критерию графика исправить отображение исходной медианы. Подготовить именную папку, сведения об ИИ и видео всех функций либо рабочий публичный адрес. Видео допустимо по ТЗ; балл за хостинг требует размещения.

## 10. После локальной демонстрации

Исправить гонку истории и подписи дробных цен. Для публичной версии проверить HTTPS, автоматическое продление сертификата, изоляцию порта API, применение квот с двух внешних IP и восстановление базы на тестовом томе.
